# Пульс стажёров: прототип на Streamlit

Рабочее название. Прототип показывает цепочку из задания: **новый ответ → приём → разбор → обновление дашборда**. Данные демонстрационные и выдуманные. Формат анкет МГТС будет известен на финале.

## Запуск (Windows)

```powershell
cd prototype
py -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python seed.py --reset          # демо-данные (59 ответов, у Павла Н. нет ноябрьского ответа стажёра)
.venv\Scripts\python receiver.py              # окно 1: приёмник ответов, http://127.0.0.1:8765
.venv\Scripts\streamlit run app.py            # окно 2: интерфейс, http://localhost:8501
```

Тесты: `.venv\Scripts\python -m unittest -v`

## Сквозной показ

1. Обзор: «Ответили в волне Ноя: 9 из 10», в очереди есть сигнал «Нет ответа стажёра» у Павла Н.
2. Боковая панель → «Имитация внешней формы» → выбран Павел Н., стажёр, Ноя → ввести комментарий (например, «Нет доступа к нужной системе, жду доступ уже неделю») и низкую оценку «Нагрузка и ресурсы» → «Отправить ответ».
3. Форма делает POST на приёмник. Приёмник отвечает сразу, а текст разбирается уже при обновлении экрана.
4. Сигнал «Нет данных» исчезает, появляются «Комментарий», «Изменение» и «Расхождение». Карточка Павла показывает цитату с пометкой «цитата найдена в источнике».
5. Повторная отправка того же `response_id` возвращает `duplicate` и ничего не меняет.

Из командной строки то же самое: `POST http://127.0.0.1:8765/response` с JSON

```json
{"response_id": "form-1", "source": "intern", "intern_id": 5, "period": 6,
 "scores": {"goals": 7, "feedback": 7, "resources": 3, "growth": 7}, "comment": "Нет доступа к нужной системе."}
```

## Как устроено

| Файл | Что делает |
|---|---|
| `core.py` | База SQLite, проверка и приём ответов, правила сигналов, разбор комментариев |
| `receiver.py` | Приёмник webhook без внешних зависимостей: `POST /response`, `GET /health`, `x-delivery-id`, необязательный `x-token` |
| `app.py` | Интерфейс Streamlit: обзор, очередь внимания, карточка стажёра, режим наставника, имитация формы |
| `seed.py` | Демо-данные, проходят через тот же приём, что и новые ответы |
| `test_core.py` | 14 проверок ядра |

Слои данных. Исходный слой `responses_raw` только пополняется, ключ `источник + response_id + версия`. Расчёты (оценки по месяцам, сигналы) каждый раз строятся заново. Результат разбора комментария хранится в кэше по хэшу текста.

Правила сигналов (пороги учебные, менять после обсуждения с HR): падение оценки на 2 и больше к прошлому месяцу; расхождение стажёра и наставника на 3 и больше по одному вопросу; нет ответа за последний месяц; комментарий с барьером и цитатой. Сигнал означает «проверить», а не оценку человека.

Что гарантирует код:
- повторная доставка одного ответа не создаёт дубль;
- исправление ответа (`version` больше) заменяет прежнее значение в расчётах;
- неверный ответ (оценка вне шкалы, неизвестный стажёр) отклоняется с причиной и пишется в таблицу `rejects`;
- пропуск ответа остаётся пропуском, ноль не подставляется;
- цитата из комментария дословно есть в тексте, иначе запись уходит на ручной разбор.

## Разбор комментариев

По умолчанию работает разборщик на правилах (`ANALYZER=keywords`): без сети и без внешней модели. Для проверки на настоящей модели предусмотрен режим `ANALYZER=llm` с OpenAI-совместимым сервером, например локальной моделью:

```powershell
$env:ANALYZER="llm"; $env:LLM_BASE_URL="http://localhost:11434/v1"; $env:LLM_MODEL="имя-модели"
```

МГТС не использует Claude и GPT для чувствительных данных, поэтому режим рассчитан на локальную open-source модель. Ответ модели проходит ту же проверку кодом (допустимые темы, дословная цитата). При ошибке сети или формата берётся разборщик на правилах. **Режим `llm` написан, но с реальной моделью не запускался.**

## Ограничения

- Формы Яндекса и Google не воспроизведены. Приёмник принимает JSON такого вида, но настоящая форма шлёт запросы из интернета на публичный адрес (Яндекс Формы используют IPv6). Это нужно сделать после получения анкет.
- Формат анкет, шкала 1–10 и 4 вопроса взяты из демонстрационного масштаба кейса. Названия вопросов и ключ связи «стажёр — наставник» надо будет заменить на выданные.
- Один ответ на сторону, стажёра и месяц: при двух ответах берётся более поздний. Как трактовать дополнительный ответ за тот же месяц, надо уточнить.
- Права доступа сделаны упрощённо (выбор роли в боковой панели), настоящей авторизации нет.
- Тема Streamlit по токенам сайта чемпионата; фирменные шрифты MTS не подключены.

## Работа с настоящими данными (другая анкета, Excel, Word, формы)

Всё, что зависит от анкеты, вынесено из кода в два файла:

- `survey.json` — вопросы (показатели), названия месяцев, шкала, темы комментариев, пороги сигналов, правила разбора без модели. Путь можно задать переменной `SURVEY_CONFIG`.
- `mapping.json` — какие колонки таблицы что значат (стажёр, наставник, месяц, оценки, комментарии). Пример: `mapping.example.json`, рабочий пример на другой анкете: `rehearsal/`.

| Команда | Что делает |
|---|---|
| `python inspect_data.py файл.xlsx` | показывает колонки и что в них лежит (оценка, дата, текст, имя); работает с .xlsx, .csv, .docx, .json и ссылкой на Google Таблицу |
| `python import_data.py mapping.json --dry-run` | читает данные и печатает отчёт: участники, ответы, неточные совпадения имён, растянутые шкалы, ошибки. В базу ничего не пишет |
| `python import_data.py mapping.json --reset` | загружает данные (повторная загрузка не создаёт дублей), затем разбирает комментарии |
| `python import_data.py mapping.json --watch 5` | то же, и каждые 5 секунд подхватывает новые строки |
| `python receiver.py` | приём `POST /response` и `POST /form/<имя источника>` (сырой ответ формы, колонки сопоставляются по mapping.json); все тела запросов сохраняются в таблице `inbox` |
| `python poll_sheet.py mapping.json --source intern` | читает Google Таблицу с ответами формы раз в несколько секунд (публичный адрес не нужен) |
| `python forms/make_google_form.py mapping.json --receiver-url https://сервер --token ТОКЕН --from-db` | создаёт Google Apps Script, который сам делает обе анкеты в Google Формах и отправляет ответы на приёмник |
| `.\run_demo.ps1 -Survey survey.json -Db pulse.db -Mapping mapping.json` | запускает приёмник и интерфейс |
| `.\bootstrap.ps1` | ставит окружение на чистый компьютер (без интернета, если рядом папка `wheels`) |

Что умеет загрузка: разные шкалы (1–5, 1–10, «4 – хорошо») приводятся к шкале проекта; несколько вопросов на один показатель усредняются; месяц берётся из колонки, из даты или из порядка строк; имена в разном написании («Соколова А.» и «Соколова Анна Петровна») склеиваются, а неточные совпадения попадают в отчёт на проверку; широкие таблицы (месяцы в колонках) разворачиваются функцией из `preprocess`.

Тесты: `python -m unittest` (24 проверки, в том числе загрузка Excel, CSV, Word и приём ответа формы по HTTP).

### Новые данные прямо в интерфейсе (боковая панель, роль HR)

- **Загрузить файл или ссылку**: выгрузка из Google Форм или Таблицы (xlsx, csv, docx, json) или ссылка на Google Таблицу. Файл загружается по сопоставлению колонок выбранного источника.
- **Подтягивать источники сами**: каждые 5 секунд перечитываются файлы и ссылки из `mapping.json`. Новая строка в таблице появляется на дашборде без кнопок, исправленная строка заменяет прежний ответ, повторы отсекаются, номера участников не меняются.
- **Заполнить ответ вручную**: поля повторяют колонки источника, ответ уходит на приёмник (`/form/<имя>`) или принимается напрямую.
