# Готовый набор в формате вебинара

Папка `mgts/` — рабочая конфигурация под данные кейса. Всё, что зависит от анкеты, лежит в трёх файлах. Код менять не нужно.

## Что известно о данных (вебинар 13 ноября)

- Две таблицы Excel (упоминали и Word): ответы стажёров и ответы наставников за один период.
- 5 стажёров, 5 наставников, 6 ежемесячных опросов. Один наставник на одного стажёра.
- Данные придуманные. У каждого стажёра и наставника уникальный ID, анкеты анонимные.
- Вопросы стажёру: как проходит стажировка, интересны ли задачи. Вопросы наставнику: как стажёр справляется, насколько оперативно и самостоятельно.
- Вопросы не меняются между месяцами. Менять анкету на ходу не нужно.
- Нужно: повторить анкету в Google Формах или похожем сервисе, ответы из формы попадают в сервис, есть интерфейс для загрузки новых данных.
- Структуру анкет и данных организаторы дадут на финале. Фирменный стиль МГТС не обязателен.

## Наши допущения (то, что организаторы не назвали)

Заложены в пример и в макет. На финале сверяем с выданными файлами.

- **Шкала:** 1–10 у обеих сторон, максимум 10. Пустая ячейка означает «ответа нет», ноль не ставится. Если шкалы окажутся другими (1–5, 1–7), загрузчик приводит их к 1–10 (`"scale": [1, 5]` в `mapping.json`).
- **Колонки:** `ID стажёра` или `ID наставника`, `Дата ответа` (ГГГГ-ММ-ДД), по колонке на каждый вопрос, колонка с комментарием.
- **Вопросы стажёра (4):** интересны ли задачи, понятны ли задачи, поддержка наставника, доступы и инструменты.
- **Вопросы наставника (3):** как стажёр справляется, насколько оперативно, насколько самостоятельно.
- **Пары вопросов для сравнения:** понятность задач и «справляется с задачами»; интерес и самостоятельность. Задаются в `survey.json` (`comparisons`).
- **Пара «стажёр и наставник»:** по числу в ID (С-03 и Н-03), если колонки с парой нет.
- **Месяц:** один ответ на человека в месяц, месяц берётся из даты. Период июнь–ноябрь 2026.
- **Комментарии:** у обеих сторон, необязательные.

## Что лежит в папке

| Файл | Назначение |
|---|---|
| `survey.json` | вопросы (показатели), шкала, месяцы, пары вопросов стажёра и наставника (`comparisons`), пороги сигналов, правила разбора комментариев |
| `mapping.json` | какие колонки таблиц что значат: ID, дата, оценки со своей шкалой, комментарии |
| `data/Ответы_стажёров.xlsx`, `data/Ответы_наставников.xlsx` | выдуманный пример в формате вебинара (59 ответов, 5 пар, 6 месяцев) |
| `templates/` | пустые шаблоны двух таблиц с листом «Как заполнять» |
| `make_data.py` | пересоздаёт пример и шаблоны |
| `build_mock.py` | пересобирает макет дашборда из расчёта прототипа (запуск из папки prototype) |
| `pulse.db` | готовая база после загрузки примера (создаётся командой ниже) |

## Формат загрузки

Таблица стажёров: `ID стажёра`, `Дата ответа` (ГГГГ-ММ-ДД, месяц берётся из даты), по колонке на каждый вопрос с оценкой, колонка с комментарием.
Таблица наставников: то же с `ID наставника`. Одна строка равна одному ответу за месяц. Пустая ячейка равна пропуску, ноль не ставить.
Пара «стажёр и наставник» определяется по числу в ID (С-03 и Н-03), если в данных нет колонки с парой. Такие пары выводятся в отчёт на проверку.

## Запуск

```powershell
cd prototype
.\run_demo.ps1 -ExecutionPolicy Bypass   # если скрипты запрещены: powershell -ExecutionPolicy Bypass -File run_demo.ps1
```

`run_demo.ps1` сам загружает данные из `mgts/mapping.json`, если базы ещё нет. Вручную:

```powershell
$env:SURVEY_CONFIG="mgts/survey.json"; $env:MAPPING_FILE="mgts/mapping.json"; $env:PULSE_DB="mgts/pulse.db"
.venv\Scripts\python import_data.py mgts/mapping.json --dry-run   # отчёт, база не меняется
.venv\Scripts\python import_data.py mgts/mapping.json --reset     # загрузка
```

## В день финала (по плану 30–40 минут)

1. Положить выданные файлы в `mgts/data/`. Посмотреть колонки: `python inspect_data.py mgts/data/<файл>.xlsx`.
2. В `mgts/mapping.json` поправить названия колонок и шкалы (`"scale": [1, 5]`).
3. В `mgts/survey.json` заменить вопросы (`dimensions`, `side_dimensions`) и пары (`comparisons`). Пары задают, что с чем сравнивать.
4. `import_data.py mgts/mapping.json --dry-run`: прочитать отчёт (пары по ID, растянутые шкалы, неточные совпадения), затем `--reset`.
5. Запустить `run_demo.ps1`. Новые ответы: боковая панель, роль HR, «Загрузить файл или ссылку» или «Подтягивать источники сами».
6. Определить сигналы и объяснить HR, почему они важны (экран «Сигналы»). Это главная часть оценки.

Проверка: `python -m unittest test_mgts test_webinar -v`.
